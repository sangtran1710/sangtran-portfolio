## Part 1: Vectors & The Dot Product

I use the **dot product** when I need a mask based on direction: snow on upward-facing rock, a highlight near a silhouette, or a response to a light.

### 1. The Core Concept: The "Alignment Sensor"

Think of it as asking how closely two arrows point the same way.

If both vectors are normalized (length of 1), the result `dot(A, B)` returns the **cosine of the angle between them**, yielding a scalar value between `-1.0` and `1.0`.

**The Surface-Normal Analogy:**
Imagine one arrow is the surface normal and the other is the direction from the surface toward the light:
1. When both arrows point in the exact same direction, alignment is perfect: **Result = 1.0**.
2. As the light direction rotates away, the value decreases smoothly.
3. At 90 degrees the arrows are perpendicular: **Result = 0.0**.
4. When pointing in opposite directions, the light is behind the surface: **Result = -1.0**.

<DotProductVisual />

> **Memory Tip:** *Same direction is 1, perpendicular is 0, opposite is -1. Dot is an alignment detector.*

### Production Use Cases

#### Procedural Snow and Dust Masking (Slope Mask)
If the `WorldNormal` of a rock mesh is dotted against the global Up vector `(0, 0, 1)`, any polygon pointing up towards the sky returns `1.0`, while vertical cliffs return `0.0`. This mask dynamically blends snow or dust across any rock in the scene.

```hlsl
// Creates a 0 to 1 gradient based on how much the surface faces up
float snowMask = saturate(dot(WorldNormal, float3(0, 0, 1)));
```

#### Fresnel Rim Lighting & Facing Masks
By dotting the Pixel's Normal against the Camera's View Direction, we can determine which pixels are facing the camera and which are on the silhouette edges. Inverting this mask produces a classic Fresnel rim light.

```hlsl
// NdotV returns 1.0 when facing the camera, 0.0 at grazing angles.
// Inverting it (1 - NdotV) highlights the outer silhouette edges!
float rimLight = saturate(1.0 - dot(Normal, ViewDirection));
```

#### Stylized Anime Cel-Shading
In realistic rendering, Lambertian diffuse lighting is calculated as `dot(Normal, LightDirection)`, creating a soft gradient from light to shadow.

When building stylized shaders, the `NdotL` value is often used as the **U-coordinate to sample a 1D Gradient Ramp Texture (LUT)**. This allows the renderer to draw hard-edged, custom-colored shadow bands that snap precisely when the light angle shifts.

### What I check before shipping

The 3D Dot Product formula is:
```hlsl
dot(A, B) = A.x*B.x + A.y*B.y + A.z*B.z
```

Shader compilers lower this expression into ALU multiply/add or fused multiply-add (FMA) instructions, and some targets have dedicated dot instructions. 

#### Check what the vectors already are
The `-1` to `1` interpretation assumes unit-length inputs. If a vector is already normalized upstream, doing it again adds work without changing the mask. If you only need the *sign* of the dot product, positive scaling does not change that sign. I check the material and profile it before treating normalization as a performance problem.

## Part 2: The Cross Product: Generating Perpendicular Vectors

![Cross Product Math](/images/shaderlex/math_cross_product.svg)

If the Dot Product is the tool for *comparing* two directions, the **Cross Product** is the tool for *generating a brand new direction*.

While less common in standard surface materials, the Cross Product is indispensable the moment you step into procedural mesh generation, particle ribbon orientation, and flow fields.

### 1. What is the Cross Product?

Unlike the Dot Product (which returns a scalar), the **Cross Product** takes two 3D vectors and returns a **brand new 3D vector**.

It solves the problem of finding a third mutually perpendicular axis:

**Vector A &times; Vector B = Vector C (Perpendicular to both A and B)**

Imagine Vector A pointing Forward, and Vector B pointing Right. Crossing A with B produces a Vector C pointing directly **Up**.

### The Right-Hand Rule
1. Point your index finger in the direction of Vector A.
2. Point your middle finger in the direction of Vector B.
3. Your thumb naturally points in the direction of the resulting Cross Product Vector.

<CrossProductVisual />

### Production Use Cases

#### Procedural Ribbon & Lightning Orientation
For a camera-facing ribbon, I can cross the ribbon's travel direction with a camera-facing direction to get an axis across its width. The order controls which side is "right." If the two input directions are nearly parallel, the result becomes very small, so a stable fallback direction is needed.

```hlsl
// Find the direction to push the left/right vertices of a particle ribbon
float3 ribbonRight = cross(RibbonForward, CameraDirection);
```

#### Stylized Wind Trails
In stylized combat effects, crossing a character's **Movement Vector** with the mesh **Surface Normal** generates a tangent vector flowing smoothly *around* the character body. Warping UV coordinates with this tangent field creates a swirling envelope of wind that contours the character in real-time.

### A small implementation note

The scalar cross product expansion contains **6 multiplications and 3 subtractions**:
```hlsl
cross(A, B) = float3(
    A.y * B.z - A.z * B.y,
    A.z * B.x - A.x * B.z,
    A.x * B.y - A.y * B.x
);
```

#### Specialization for Fixed Axes
When crossing a Forward vector with a fixed world axis like `Up = (0, 0, 1)`, modern compilers readily constant-fold zero terms. If profiling identifies this as a critical hot path on mobile hardware, the swizzle can be written directly:

```hlsl
// Simplified cross product when crossing with (0, 0, 1)
float3 RightVector = float3(Forward.y, -Forward.x, 0.0);
```

> [!WARNING]
> **Direction check:** Cross-product order flips the result (`A x B = -(B x A)`). If a ribbon faces the wrong way, check the input order and the engine's coordinate convention.

## Part 3: UV Mathematics & Texture Distortion

![UV Coordinates Grid](/images/shaderlex/math_uv_coords.svg)

Manipulating the 2D coordinate space before sampling a texture is the engine behind fluid streams, scrolling energy beams, heat haze, and organic surface dissolution.

### 1. The UV Coordinate Space (Cartesian Grid)

In shader programming, `UV` (or `TexCoord`) is a 2D coordinate `[U, V]` mapping a flat 2D image onto 3D geometry:
- `[0, 0]` represents the top-left (Direct3D / Unreal) or bottom-left (OpenGL / Unity) corner.
- `[1, 1]` represents the opposite diagonal corner.

<UvCartesianVisual />

UVs are not limited to the `[0, 1]` range. Values outside this interval trigger texture sampler wrapping, clamping, mirroring, or border padding depending on sampler settings.

### 2. UV Panning (Addition & Time)

Panning creates the illusion of continuous flow without deforming vertex geometry. Adding an offset to the UV coordinate shifts the sampling position over time.

```hlsl
// Basic linear panning
float2 pannedUv = BaseUV + (Time * float2(0.5, 0.0));

// Wobbly panning using Sine
float wobble = sin(Time * 3.0) * 0.1;
float2 wobblyUv = BaseUV + float2(Time + wobble, 0.0);
```

<UvPanningVisual />

**In practice:** If a scrolling texture stretches at the edge, I check whether the sample is using **Wrap / Repeat**. With **Clamp**, out-of-range UVs keep sampling the edge color.

### 3. UV Distortion (Noise & Flow Maps)

Adding smooth pseudorandom offsets to UV coordinates warps space organically, creating convincing refraction, turbulence, and shockwaves.

```hlsl
// Sample two independent channels to get a 2D offset
float2 distortionSample = tex2D(NoiseSampler, UV).rg;

// Remap both channels from [0, 1] to [-1, 1]
float2 centeredOffset = (distortionSample * 2.0) - 1.0;

// Offset U and V independently
float2 distortedUv = BaseUV + (centeredOffset * DistortionStrength);
```

<UvDistortionVisual />

> [!TIP]
> **Centering & Diagonal Bias:** Always subtract 0.5 or remap to `[-1, 1]` so the distortion pushes equally in all directions rather than drifting diagonally up-right. Use two distinct noise channels for U and V to prevent 45-degree sliding artifacts.

## Part 4: Spatial Masks & World Position Math

![Spatial Distance Falloff](/images/shaderlex/math_spatial.svg)

While UV coordinates live in 2D texture space, production VFX materials frequently need to interact with the 3D game world: soft particle intersections, terrain-hugging decals, and vertex displacement.

### 1. The Spherical Mask (Distance Falloff)

Spherical masks create localized radial gradients—essential for forcefields, explosion shockwaves, and proximity reveals.

The core math relies on the Euclidean `distance()` function between the pixel's `WorldPosition` and an `EffectCenter` point:

```hlsl
// Calculate distance from effect center to current shaded pixel
float dist = distance(WorldPosition, EffectCenter);

// Normalize to 0..1 by max radius and invert
float sphereGradient = saturate(dist / MaxRadius);
float sphereMask = 1.0 - sphereGradient;
```

<SphericalMaskVisual />

**Common Mistake:** In Unreal Engine, `ObjectPositionWS` is the bounding center of the entire mesh, not the local shaded pixel. For effects that span across multiple meshes (like ground shockwaves), use `WorldPosition` (Absolute World Position) rather than object center.

### 2. World Position Offset (WPO)

World Position Offset (WPO) moves mesh vertices in the material. For a simple flutter or pulse, it can give me motion without adding an animation asset. The mesh still needs enough vertices for the shape to bend.

```hlsl
// Inflate and deflate geometry along surface normals
float3 WPO = VertexNormal * sin(Time * Speed) * Amplitude;
```

<WorldPositionOffsetVisual />

**Bounding Box Culling:** Aggressive WPO can push vertices outside their precomputed mesh bounding box, causing the mesh to flicker or pop out of view when the camera looks away. Configure **Max World Position Offset Displacement** or increase mesh bounds scale to accommodate the displacement.

### 3. Depth Fade (Soft Intersections)

When translucent particle quads (smoke, fire, energy shields) intersect opaque world geometry, they produce harsh, unnatural cutting lines.

**Depth Fade** eliminates this artifact by measuring the view-depth distance between the translucent pixel (`PixelDepth`) and the solid geometry rendered behind it (`SceneDepth`):

```hlsl
// View-depth separation between opaque background and translucent pixel
float depthDifference = SceneDepth - PixelDepth;

// Smooth fade to zero opacity as distance approaches zero
float depthFadeMask = saturate(depthDifference / FadeDistance);
float finalOpacity = BaseOpacity * depthFadeMask;
```

## Part 5: Timing and Soft Edges

These are the small functions I reach for when an effect needs a pulse, a clean edge, or a repeating pattern.

### 1. Trigonometry: Sine and Cosine

Sine and Cosine transform linearly increasing inputs (like game time) into continuous cyclic oscillations between `-1.0` and `1.0`.

```hlsl
// Remaps a -1 to 1 sine wave into a 0 to 1 range for opacity pulsing
float pulsingMask = sin(Time * Speed) * 0.5 + 0.5;
```

<SineWaveVisual />

#### When the material gets expensive
Sine is handy for a pulse, but one `sin()` node is not a performance verdict. The cost depends on the shader, GPU, and how many pixels run it. If profiling points to this material, I first look for repeated calculations; then I compare a simpler wave or a texture lookup and check whether the visual still holds up.

### 2. Step and Smoothstep (Edge Thresholds)

Stylized shaders often require turning soft gradients into crisp color bands (e.g. anime fire, comic ink lines).

- `step(edge, x)`: Returns `0.0` if `x < edge`, else `1.0`. Can cause temporal aliasing on fine lines.
- `smoothstep(min, max, x)`: Smooth Hermite interpolation between 0 and 1.

```hlsl
// Screen-space anti-aliased edge thresholding
float edgeWidth = max(fwidth(NoiseValue), 1e-5);
float antiAliasedMask = smoothstep(0.5 - edgeWidth, 0.5 + edgeWidth, NoiseValue);
```

<StepVsSmoothstepVisual />

`fwidth()` can size the transition to roughly a pixel. It often helps thin bands stay calmer as the camera moves, but I still check the result in motion, especially after temporal upscaling.

### 3. Fract and Floor (Infinite Tiling & Pixelation)

- `fract(x)`: Extracts the fractional part `x - floor(x)`, creating an endless sawtooth ramp from `0.0` to `1.0`.
- `floor(x)`: Snaps values down to the nearest integer, useful for procedural mosaics and retro pixelation.

```hlsl
// Infinite sawtooth wave for scanning lines
float scanline = fract(Time * Speed);

// Retro 64x64 mosaic pixelation
float2 pixelatedUv = floor(UV * 64.0) / 64.0;
```

## Summary & References

I keep returning to these operations because each one answers a visual question. Which direction faces up? Where does the pattern move? How far is this pixel from the impact? Here's my quick way back to the right tool:

- **Which way does it face?** `dot()` for slope masks and rim lighting; `cross()` for a perpendicular ribbon axis.
- **Where does the pattern go?** UV offsets and distortion for scrolling energy, flow, and heat haze.
- **How close is it?** `distance()` for radial masks; depth difference for soft particle intersections.
- **How does it change over time?** `sin()` for a pulse, `smoothstep()` for a controlled edge, `fract()` for repetition.
