Scrolling normal maps on a flat plane to simulate water is a classic beginner mistake. While it looks okay from high angles, it falls apart completely when the camera moves close to the horizon because the water profile remains perfectly flat and fake.

To make water look real, you need actual height movement on the vertices. Simple sine waves create a soft, jelly-like look. To get the sharp, crested waves seen in AAA games, we use **Gerstner Waves**.

---

## What is a Gerstner Wave?


A Gerstner wave (or trochoidal wave) is a physical approximation of deep-water waves.
- **Sine Wave:** Moves vertices strictly up and down (Z-axis). This results in rounded crests and rounded troughs.
- **Gerstner Wave:** Shifts vertices horizontally (X and Y-axes) toward the crests while pushing them vertically (Z-axis). This pulls the vertices together, pinching the crests into sharp points while flattening the troughs, which matches real-world ocean physics.

## To calculate a Gerstner wave, we offset a vertex position `P = (x, y, z)` by a displacement vector `D = (dx, dy, dz)` calculated as:

- `dx = dir_x * amplitude * cos(k * (dir_xy) - c * t)`
- `dir_y * amplitude * cos(k * (dir_xy) - c * t)`
- `dz = amplitude * sin(k * (dir_xy) - c * t)`

Where:
- `dir = (dir_x, dir_y)` is the normalized horizontal direction vector of the wave.
- `amplitude` is the wave height.
- `k` is the wave number, calculated as: `k = 2 * PI / waveLength`
- `c` is the phase speed, calculated from gravity as: `c = sqrt(g / k)`
- `t` is time.

By summing multiple wave vectors (usually 4 waves with varying wavelengths and angles), we get complex, non-repeating ocean patterns.

## Custom HLSL Wave Function

Here is the HLSL code representing a single wave offset:

```hlsl
// Trochoidal Gerstner Wave math offset
float3 GerstnerWave(float2 uv, float waveLength, float amplitude, float speed, float2 dir, float time)
{
    float g = 9.8; // Gravity constant
    float k = 2.0 * 3.14159 / waveLength;
    float c = sqrt(g / k); // Phase speed based on physics
    float2 d = normalize(dir);
    float f = k * (dot(d, uv) - c * speed * time);
    
    float3 offset;
    offset.x = d.x * (amplitude * cos(f));
    offset.y = d.y * (amplitude * cos(f));
    offset.z = amplitude * sin(f);
    return offset;
}
```

## Step-by-Step Implementation in UE5

### Step 1: Geometry Setup
Vertex shaders cannot create triangles; they can only move existing vertices. If you apply this shader to a flat plane with 4 vertices, nothing will happen. You must subdivide the water plane heavily, or use **Virtual Heightfield Mesh (VHM)** or distance-based **Tessellation/Nanite** in UE5 to provide enough geometry.

### Step 2: Summing Waves
To prevent a repetitive, mechanical pattern, call the wave function 4 times with different directions, wavelengths, and speeds, and sum the offsets:
```hlsl
float3 w1 = GerstnerWave(worldPos.xy, 1000, 30, 1.0, float2(1, 0), time);
float3 w2 = GerstnerWave(worldPos.xy, 600, 15, 1.5, float2(0.7, 0.7), time);
float3 w3 = GerstnerWave(worldPos.xy, 300, 5, 2.0, float2(-0.2, 0.9), time);

float3 totalWPO = w1 + w2 + w3;
```
Connect this sum directly to the **World Position Offset** input on your material node.

## Common Production Traps & Solutions

### 1. Normal Calculations (The "Flat Shading" Bug)
**Why it happens:** Moving vertices in the vertex shader does not update the surface normals automatically. If you don't calculate new normals, your waves will move but light will bounce off them as if the plane was completely flat.
**How to fix it:** You must compute the partial derivatives of the wave equation to construct a new tangent-space normal, or sample the height offset in a tiny offset cross (finite differences method) to generate a displacement normal map.

### 2. Mesh Tearing & Bounds Scale
**Why it happens:** When waves get high, the mesh coordinates move beyond the original bounding box of the actor. The engine thinks the water is off-screen and aggressively culls (disappearing) it.
**How to fix it:** Select the water mesh actor in your level and increase the **Bounds Scale** parameter (e.g. from `1.0` to `2.5`) to prevent culling.
