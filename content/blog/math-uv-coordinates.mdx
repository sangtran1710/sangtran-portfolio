Understanding UV math is foundational for real-time VFX. By manipulating the UV grid before sampling a texture, static images can be transformed into dynamic effects like flowing water, heat distortion, or scrolling UI.

Here is a breakdown of how UV coordinates work and how they are commonly distorted in production pipelines.

> **Code note:** The snippets are engine-agnostic shader pseudocode. Replace `BaseUV`, `Time`, texture objects, and sampler calls with the equivalents provided by the target engine.

---

## 1. The UV Coordinate Space (Cartesian Grid)

In shader programming, `UV` (or `TexCoord`) is simply a 2D vector `[X, Y]` (or `[U, V]`) that tells the renderer how to map a flat 2D texture onto a 3D polygon. 

### What it solves
UV math allows us to shift, scale, and rotate *where* the pixels of a texture are being read from the source image.

The base texture domain is conventionally described from **0.0 to 1.0**, but UV coordinates are not restricted to that range. Negative values and values above 1.0 are valid; the sampler's Wrap, Clamp, Mirror, or Border mode decides what happens outside the base tile.
- `[0, 0]` is the top-left corner (in DirectX/Unreal) or bottom-left (in OpenGL/Unity).
- `[1, 1]` is the opposite corner.

<UvCartesianVisual />

By mathematically altering this `[0..1]` grid before plugging it into a Texture Sample, the resulting image can be natively warped on the GPU.

## 2. UV Panning (Addition & Time)

The simplest and most commonly used form of texture animation is **Panning**. 

### What it solves
Panning shifts the texture over time, creating the illusion of endless forward movement without requiring moving geometry.

### Production Use Case: Scrolling Energy Beams
If UV coordinates control where the texture is sampled, adding a constantly increasing number to them will shift the sampling position. By taking the global `Time` variable and adding it to the `U` or `V` channel, I can make textures shift infinitely. 

While Unreal Engine provides a built-in `Panner` node, doing it manually via `Add` allows me to inject non-linear time, like sine waves. In production, I use this to create "wobbly" or "breathing" panning effects for sci-fi lasers or waterfalls.

```hlsl
// Basic linear panning
float2 pannedUv = BaseUV + (Time * float2(0.5, 0.0));

// Wobbly panning using Sine
float wobble = sin(Time * 3.0) * 0.1;
float2 wobblyUv = BaseUV + float2(Time + wobble, 0.0);
```

<UvPanningVisual />

### Common Mistake
A common error is forgetting to set the texture's Sampler State to "Wrap" (or Tile) in the engine. If the texture is set to "Clamp", panning the UVs beyond 1.0 will just stretch the edge pixel infinitely instead of looping the image.

### When not to use it
Avoid using UV Panning to simulate physical movement of rigid objects (like a conveyor belt moving crates). UV panning only slides the paint on the surface, it doesn't move the physical bounds of the mesh, which can break collisions and lighting.

## 3. UV Distortion (Noise & Refraction)

If adding a constant number pans the texture evenly, adding *random* numbers to different parts of the UV grid warps the coordinate space itself. 

### What it solves
Distortion breaks up the rigid grid structure, simulating natural organic flow or optical refraction.

### Production Use Case: Refraction and Heat Haze
When building heat haze or water shaders, a grayscale Noise texture (or a Flow Map) is typically added to the base UVs. When the main texture (or the Scene Color buffer) is sampled using this warped grid, the image appears distorted, melted, or refracted like hot air.

```hlsl
// Sample two independent channels to get a 2D offset.
float2 distortionSample = tex2D(NoiseSampler, UV).rg;

// Remap both channels from [0, 1] to [-1, 1].
float2 centeredOffset = (distortionSample * 2.0) - 1.0;

// Offset U and V independently.
float2 distortedUv = BaseUV + (centeredOffset * DistortionStrength);
```

<UvDistortionVisual />

### Common Mistake: Biased or Diagonal Distortion
Adding an uncentered `0.0` to `1.0` signal biases the offset in the positive direction. A second issue is using one grayscale channel as a `float2`: both U and V then receive the same value, so the distortion follows a diagonal. I use two independent channels (or two decorrelated samples), center both around zero, and inspect the flow direction before increasing strength.

### When not to use it
Avoid extreme UV distortion on recognizable features such as text or faces. Large, rapidly changing offsets can stretch features, expose sampler boundaries, and produce unstable mip selection. The exact artifact depends on texture resolution, derivatives, filtering, and sampler mode rather than distortion strength alone.
