Simulating flowing fluids (like lava, rushing rivers, or swirling clouds) in real-time is too expensive for game engines if you use full physics grid solvers. Instead, technical artists use **Flow Maps**.

A flow map is a 2D texture where the Red and Green channels store 2D direction vectors (X and Y). The shader uses these vectors to distort the UV coordinates of a tiled noise texture over time, creating the illusion of liquid movement.

---

## The Concept of Phase Swapping


If you just offset UV coordinates along the flow direction continuously, the texture will stretch and warp until it turns into ugly, dragged-out pixels.

To make the flow infinite without stretching forever, we use a technique called **Phase Swapping** (or double-buffered panning):
1. We pan **two identical copies** of the texture.
2. **Phase A** starts at time `0` and fades in, distorting along the flow vector.
3. **Phase B** is offset by half a cycle (half phase). When Phase A is fully distorted and about to reset, Phase B is fully clear and has taken over.
4. We blend between the two phases using a sine wave, hiding the warp reset point.

## Flow Map Math

To reconstruct the flow vectors from the flow map texture:
- Color values in a texture range from `0.0` to `1.0`.
- Vectors must point in both positive and negative directions (from `-1.0` to `1.0`).
- We remap the texture coordinates:

`Flow Vector = (Texture Color * 2.0) - 1.0`

---

## Custom HLSL Implementation

Here is the HLSL code block representing a two-phase flow map UV distortion:

```hlsl
// Remap Flow Map color from [0, 1] to [-1, 1] vector space
float2 flowVector = (FlowMapTex.Sample(FlowSampler, uv).rg * 2.0) - 1.0;
flowVector *= flowStrength;

// Calculate two phases offset by 0.5 (half phase)
float phase0 = frac(time * flowSpeed);
float phase1 = frac(time * flowSpeed + 0.5);

// Distort UVs along the flow vector for each phase
float2 uv0 = uv - flowVector * phase0;
float2 uv1 = uv - flowVector * phase1;

// Sample the noise texture twice
float4 tex0 = NoiseTex.Sample(NoiseSampler, uv0);
float4 tex1 = NoiseTex.Sample(NoiseSampler, uv1);

// Calculate the blend weight (cycles between 0 and 1)
float blendWeight = abs(0.5 - phase0) / 0.5;

// Interpolate between the two distorted textures to hide resets
float4 finalFlowColor = lerp(tex0, tex1, blendWeight);
```

## Unreal Engine Setup Guide

Unreal Engine has a built-in **FlowMap** node, but it is easy to build from scratch:

1. Create a **Texture Sample** for your flow map.
2. Add a **Multiply** node by `2.0` and **Subtract** by `1.0` to remap the values.
3. Multiply the remapped flow direction by the output of a **Time** node.
4. Subtract the result from your base noise UVs.
5. Use this distorted UV to sample your water/fire texture.

*Note:* To implement phase-swapping in the graph, duplicate the UV math with a `Frac` node offset by `0.5`, sample the texture twice, and use a `LinearInterpolate (Lerp)` node to blend them.

## Common Production Traps & Solutions

### 1. The "Texture Compression" Trap
**Why it happens:** When you import a flow map, the engine compresses it as a standard color texture (sRGB/BC1). This compression strips out vector detail and blocks negative values, making your liquid flow in weird, blocky, one-directional angles.
**How to fix it:** Always open the flow map texture details in Unreal Engine and set the **Compression Settings** to **VectorDisplacementMap (BC7)** or **TC_Normalmap**, and disable **sRGB**. This preserves the raw mathematical precision of the vectors.

### 2. High Flow-Rate Warping
**Why it happens:** If you set the flow speed or strength too high, the textures warp aggressively and the phase-swap transition becomes visible as a pulsing overlay.
**How to fix it:** Keep the flow strength small, or use high-frequency noise textures where warp details are harder for the human eye to track.
